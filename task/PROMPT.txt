实现敏感配置变更的离线补偿账本。以配置键、值标识、分类和单键版本为输入，原事务可同时改多个键，保存每键旧值及新版本。补偿申请引用原事务和允许执行的时间窗口。只允许撤回完整原事务；如果当前键由后续原事务写入，须先完整补偿那个事务；撤销某事务后，键的有效写入来源回到上一个尚未撤销的事务，但单键版本继续增加。审核人按回退事务及当前目标键版本签发决定，时窗内有效、仅可消费一次。同一审核人可批准互不重叠的不同事务；对任一键，按补偿序列筛出涉及该键的步骤，相邻两步必须选择不同的审核人。同一步有多份合格审核时可任选一份。
plan 在固定逻辑时刻求目标事务的可执行完整回退前缀，返回最短事务序列，再按事务 ID 和审核 ID 组成的序列决胜；每一步按前序模拟结果核对版本，闭包不可满足时解释最早缺的审核或前置事务。apply 以计划绑定的键版本和审核 ID 原子提交完整序列，任一过期、撤销或写入竞争使整笔失败。支持并发 SQLite 客户端，幂等申请有稳定回执。验证跨键菱形依赖、逐键版本递增、补偿后同值但旧审核失效、规划后无关键变更、关联键并发、持久化故障及两份审核冲突。

回退序列还必须保持服务不变式。输入给出每键的有限值域，以及若干必须始终成立的约束：对列出的键值组合，激活键的值落在激活集合内时，同组其他键同时满足各自的允许集合。启动状态、每一步完整补偿后的状态及最终状态均须满足；不变式不能仅在最外层事务结束时校验，不能发布中间态。允许为了消除跨键不变式附加地补偿闭包外获准的事务，额外影响代价按被补偿事务输入权重计。原规划目标改为先最小化闭包外代价，再最小化总补偿步数，最后按 (事务 ID,审核 ID) 序列决胜。apply 核对计划依赖的全部读写键（含不变式只读键）版本和政策代次，验证并保存每一步逻辑回执，任何失败不提交。输入规模至多 24 个仍有效事务、80 键，须复用等价状态且用穷举小样对拍。测试加入两条不同的合法顺序却采用不同审核后缀、最后状态合法但中间违反不变式、回退闭包外的事务才有解、不变式只读键被并发修改、审批 ID 相同的重放和回执后的进程退出。

使用 Windows 原生 Python 3.12、标准库和 CPU，从空仓库实现，所有夹具用本地虚构数据。命令格式为 python -m solution <命令> CASE.json，涉及持久状态的命令带 --db DB.sqlite。标准输出为 UTF-8 JSON，同一逻辑输入产生同一结果；结构错误给出可定位的错误码及字段位置。交付可直接运行的样例、README（含完整输入输出定义与复现命令）和可用 python -m unittest discover -s tests -v 执行的断言测试。
